# Offline URL analysis

FocusGuard reuses the user-supplied `mlp02/final_model/model.pkl` random forest and adapts its lexical feature extractor. There is no external prediction API, MongoDB scan logging, URL request, redirect follow, or Python runtime in the installed extension. The web companion downloads static model data from its own server; the URL itself stays in browser memory.

## What changed

The old checker only accepted absolute URLs and reported HTTPS plus a handful of traits. The new checker accepts bare domains, validates hostnames and ports, rejects executable schemes and ambiguous whitespace/backslash inputs, identifies the actual destination behind embedded credentials, and checks shortened links, internationalized hostnames, IP literals, long addresses and deep subdomains. A report can be downloaded without including the path, query, credentials or original input.

The same module runs in the companion, extension popup, full extension dashboard and active-tab worker action. No API key is required.

## Model provenance and limitations

- Original artifact: `mlp02/final_model/model.pkl`, a scikit-learn 1.5.1 binary RandomForestClassifier with 128 trees and 30 inputs. Training code maps the dataset's phishing label -1 to model class 0; class 1 denotes legitimate examples.
- `extension/models/url-forest.json` records the source artifact SHA-256, feature order, class mapping and tree nodes. It contains inert JSON, without the imputer's training rows. `public/focusguard-url-model.json` is the web copy.
- Eight lexical inputs are observed: IP literal, URL length, shortening service, @ symbol, repeated path slashes, hostname hyphen, hostname label depth, and HTTPS text in the hostname. The supplied subdomain feature uses label depth, without a public suffix list; it is an approximation for domains such as `example.co.uk`.
- Twenty-two inputs are unknown, including certificate validation, page content, registration age, WHOIS consistency, redirects, DNS and reputation. The original URL extractor's neutral-zero placeholders and HTML/certificate proxies are **not** used as observed evidence.
- Each tree explores feasible leaves for missing inputs in the dataset's {-1, 0, 1} feature domain. Repeated tests of an unknown feature retain their constraints. Averaging per-tree minima/maxima gives conservative bounds on the forest's phishing score. Bounds may be wider than the jointly attainable range. They are **not** confidence intervals, calibrated probabilities, or an accuracy measurement.
- If the bounds cross 0.5, the interface says **Inconclusive**. Address warnings remain visible independently. Internal/local addresses skip the public-site model. A missing asset produces an explicit model-unavailable result while preserving address checks.
- No saved evaluation report was supplied with the artifacts. Feature-vector inference parity validates the port, not real-world phishing detection accuracy. A clean URL or legitimate-leaning score does not establish safety.

These limits follow from inspecting the supplied feature extractor and training pipeline. Scikit-learn documents [RandomForestClassifier inference](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.RandomForestClassifier.html) and [model persistence compatibility](https://scikit-learn.org/stable/model_persistence.html).

## Reproduce the export

Use Python 3.12 with `scikit-learn==1.5.1`, `numpy==2.1.0`, `scipy==1.14.1`, `joblib==1.4.2` and `threadpoolctl==3.7.0` in an isolated environment. Only load your trusted local artifacts. The exporter uses an explicit sklearn/numpy type allowlist and verifies that the supplied KNN imputer leaves complete inputs unchanged.

```sh
python scripts/export_url_model.py /path/to/mlp02
npm run package:extension
npm run test:extension
```

Export generates 128 reference feature vectors and sklearn scores. The Node tests compare the browser forest against these reference scores to 1e-12, check complete/unknown-feature bounds, compare ten URL feature vectors generated by the original Python extractor, and exercise malformed URLs, hidden destinations, model failure and internal-address handling.

## Recruiter demonstration

Open URL check and try **Ordinary link**, **Hidden destination** and **Shortened link**. Show that HTTPS does not remove the hidden-destination warning. Explain why missing evidence makes the model inconclusive. Download the redacted report and use the hostname in a focus rule. Describe the project as offline URL risk analysis with an experimental phishing model; do not claim validated malware protection or accuracy.
